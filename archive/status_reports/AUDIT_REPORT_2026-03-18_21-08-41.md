## 2. Project purpose and current architecture

### Purpose

`traminex` is a first-release Python package for categorical sequence analysis inspired by TraMineR and TraMineRextras. The implementation goal is not just a thin wrapper around documentation. The project is trying to ship:

- A Python-native state-sequence object model (`STSList`, `SeqMD`)
- Format conversion between wide, long, spell, and event representations
- Core sequence statistics and complexity metrics
- Sequence distances with Python, Numba, and optional compiled backends
- Event-sequence mining utilities
- Basic clustering, representative extraction, and tree-style models
- Plotting helpers for sequence analysis workflows
- A parity-tracking toolchain against TraMineR and TraMineRextras source packages

### Architectural shape

The package is organized coherently at a high level:

- `traminex/__init__.py`
  - lazy top-level API export layer driven by `traminex/api_manifest.py`
- `format.py`, `seqformat.py`
  - sequence construction and representation conversion
- `stats*.py`
  - split stats implementation with a facade in `stats.py`
- `distances/`
  - dispatcher, cost builders, Python kernels, and OM local variants
- `events.py`
  - event sequence model and mining utilities
- `cluster.py`, `diss.py`, `diss_p1.py`, `disstree.py`, `seqtree.py`
  - downstream analytics on distance matrices or derived features
- `visualization/`
  - plotting and helper utilities

This is a sensible first-release layout. The main architectural weakness is not top-level structure. It is semantic duplication: the same concepts are reimplemented in several places with slightly different rules, especially around state encoding, missing/void handling, alphabet ordering, event ordering, and public option semantics.

## 3. Executive summary

The codebase is in materially better condition than a typical `0.0.1` port:

- The core package imports cleanly.
- The public API is manifest-driven and lazy-loaded.
- The test suite is large and currently green.
- The distance layer has a real fallback hierarchy instead of a stub architecture.
- There is clear evidence of deliberate effort around parity tracking, documentation, and stubs.

However, the current release is not semantically clean enough to call the parity story reliable yet. The biggest problems are not gross crashes in the main happy path. They are silent contract violations:

- Missing-state metadata is not propagated consistently across constructors.
- Event ordering guarantees are false when timestamps tie.
- A top-level plotting helper crashes when state labels exist.
- Some public parameters and variants are documented and exposed but not actually implemented.
- Generated audit/parity artifacts are stale and contradict the current manifest.

Because this is the first public release and backward compatibility is explicitly not required, several placeholder or misleading options should be removed now instead of being carried forward.

## 5. Findings

### High 1. Missing-state metadata is not propagated consistently across constructors

Affected files:
- `traminex/seqformat.py:69-76`
- `traminex/format.py:148-163`
- `traminex/format.py:399-404`
- `traminex/format.py:560-567`

Problem:
- `seqdef()` sets `nr_code` and `void_code`.
- `seqdef_from_long()` constructs `STSList` directly and does not set `nr_code` / `void_code`.
- `TSE_to_STS()` delegates to `seqdef_from_long()`, so it inherits the same problem.
- `HSPELL_to_STS()` often returns through `_encode_state_matrix()`, which also constructs `STSList` directly without `nr_code` / `void_code`.

Impact:
- Functions that rely on `nr_code` / `void_code` silently mis-handle missing/void states for objects created from long/spell pipelines.
- This affects statistics, plotting, and any `include_missing=False` behavior.

Concrete repro run during audit:

```python
long = pd.DataFrame({
    "id": [1, 1, 2, 2],
    "time": [1, 2, 1, 2],
    "state": ["A", "*", "A", "B"],
})
x = tx.seqdef_from_long(long, nr="*")
print(x.nr_code)  # None
print(tx.seqtabstocc(x, include_missing=False))
```

Observed output:
- `nr_code` is `None`
- `seqtabstocc(..., include_missing=False)` still includes `*` in the output patterns

Assessment:
- This is a real correctness bug, not a cosmetic inconsistency.
- It also means tests currently validate missing handling only through `seqdef()`-constructed objects, not through the alternate constructors that users will actually use for long/spell workflows.

Recommendation:
- Centralize all STS construction through a single internal encoder that always computes:
  - alphabet ordering
  - labels / palette alignment
  - `nr_code`
  - `void_code`
  - start / xtick metadata
- Do not construct `STSList` directly in multiple conversion functions unless the metadata contract is enforced in one place.

### High 2. Event ordering guarantees are false when timestamps tie

Affected files:
- `traminex/events.py:115`
- `traminex/events.py:382`
- `traminex/events.py:508`
- `traminex/events.py:551`

Problem:
- `seqecreate()` claims: "ties within an id preserve original order".
- Downstream event functions sort stored `(time, label)` tuples with `items.sort()`.
- When timestamps tie, tuple sorting uses the label as a tiebreaker, not original row order.

Impact:
- `seqefsub`
- `events_transition_matrix`
- `frequent_event_pairs`
- `frequent_event_pairs_timegap`

all reorder simultaneous events lexicographically, not stably.

Concrete repro run during audit:

```python
df = pd.DataFrame({
    "id": ["i1", "i1", "i1"],
    "timestamp": [1, 1, 2],
    "event": ["B", "A", "C"],
})
ev = tx.seqecreate(df)
print(tx.frequent_event_pairs(ev))
```

Observed output:
- The pair sequence behaves as if the two events at time `1` were ordered `A, B`, not `B, A`

Assessment:
- This is a data semantics bug.
- The implementation contradicts its own docstring and can change pattern-mining and transition outputs for valid input.

Recommendation:
- Preserve an input-order index in `EventSequence`.
- Sort by `(time, original_order)` instead of `(time, label)`.
- Add regression tests for tied timestamps in all event utilities, not just one function.

### High 3. `events_to_state_sequences()` crashes on explicit `states=...` when `fill` is outside the provided alphabet

Affected file:
- `traminex/events.py:455-464`

Problem:
- When `states` is explicitly supplied, `all_states = states`.
- The function still fills blank time points with `fill`.
- If `fill` is not in `states` and `align_missing=False`, `code[fill]` lookup fails during vectorization.

Concrete repro run during audit:

```python
ev = tx.seqecreate(pd.DataFrame({
    "id": ["i1", "i1"],
    "timestamp": [2, 3],
    "event": ["A", "B"],
}))
tx.events_to_state_sequences(
    ev,
    states=["A", "B"],
    time_grid=[1, 2, 3],
    fill="_",
    align_missing=False,
)
```

Observed output:
- `KeyError: '_'`

Impact:
- A public API crashes on a reasonable explicit-state use case.
- The failure mode is not validated early and the error is not user-friendly.

Recommendation:
- If `fill` is used in generated rows, it must either:
  - be inserted into the alphabet automatically, or
  - be rejected up front with a clear validation error.
- Prefer explicit validation over an internal `KeyError`.

### High 4. Cluster chronogram helpers crash when state labels are present

Affected file:
- `traminex/visualization/plots/chronogram.py:87`
- `traminex/visualization/plots/chronogram.py:182`

Problem:
- These functions build cluster-specific `STSList` objects.
- They slice `x.labels` using sequence row indices:
  - `labels=None if x.labels is None else [x.labels[i] for i in rows]`
- But `x.labels` is state-label metadata and should have length equal to alphabet size, not number of sequences.

Impact:
- If the input `STSList` has state labels, both:
  - `cluster_chronograms()`
  - `cluster_chronograms_with_representatives()`

can crash or corrupt label semantics.

Concrete repro run during audit:

```python
x = tx.seqdef(
    np.array([["A", "B"], ["A", "B"], ["B", "A"]], dtype=object),
    labels=["Alpha", "Beta"],
)
cluster_chronograms(x, np.array([0, 0, 1]))
```

Observed output:
- `IndexError: list index out of range`

Recommendation:
- Preserve state metadata unchanged:
  - `labels=list(x.labels)` if not `None`
  - `cpal=list(x.cpal)` if not `None`
- Only slice sequence-level structures such as `data` and `weights`.

### High 5. Public distance variants and parameters are exposed but not implemented as advertised

Affected files:
- `traminex/config_dataclasses.py:80-87`
- `traminex/distances/python_kernels.py:414`
- `traminex/distances/python_kernels.py:464`
- `traminex/distances/python_kernels.py:623-626`
- `traminex/distances/__init__.py:159`

Problem A: DHD `traminer` / `tmean`
- `DHDConfig` advertises:
  - `variant="traminer"`
  - `variant="tmean"`
- Runtime implementation maps both to the plain `"mean"` path.
- No distinct TraMineR-style weighting or entropy-weighted logic exists.

Concrete repro run during audit:

```python
D_mean = tx.seqdist(x, method="DHD", variant="mean")
D_tram = tx.seqdist(x, method="DHD", variant="traminer")
D_tmean = tx.seqdist(x, method="DHD", variant="tmean")
```

Observed:
- `D_mean == D_tram == D_tmean`

Problem B: DUR `eps`
- `DURConfig` exposes `eps`.
- Runtime `DUR` chi-square dispatch does not pass `eps` into either the Numba or Python branch.

Concrete repro run during audit:

```python
D1 = tx.seqdist(x, method="DUR", metric="chi2", eps=1e-12)
D2 = tx.seqdist(x, method="DUR", metric="chi2", eps=1.0)
```

Observed:
- `D1` and `D2` are identical

Impact:
- The public API contract is misleading.
- Stubs and docs reinforce options that currently do nothing or alias silently.
- For a `0.0.1` first release, this is exactly the kind of surface that should be removed rather than preserved as placeholder compatibility.

Recommendation:
- Either implement these semantics fully now or remove them now.
- My recommendation for `0.0.1`:
  - remove `traminer` and `tmean` from `DHDConfig` and runtime validation until implemented
  - remove `eps` from `DURConfig` and dispatcher, or plumb it through correctly

### Medium 6. `TSE_to_STS()` is materially less capable than the reference function but parity docs overstate equivalence

Affected files:
- `traminex/format.py:148-163`
- `traminex/seqformat.py:54-76`
- `SOURCES/TraMineRextras/R/TSE_TO_STS.R:1`
- `docs/API_PARITY.md:47`
- `docs/API_PARITY.md:70`
- `docs/API_PARITY.md:83`

Problem:
- The Python `TSE_to_STS()` is explicitly described in code as a "Minimal equivalent".
- It simply renames columns and calls `seqdef_from_long()`, which is effectively a pivot.
- The reference TraMineRextras function supports event-to-state transformation semantics with:
  - `stm`
  - `tmin`
  - `tmax`
  - `firstState`
  - ordered event processing

Additional issue:
- Current workflows pass `fill="_"` into `TSE_to_STS()`, but `seqdef_from_long()` silently ignores it because only a small metadata whitelist is forwarded into `STSList`.

Impact:
- The same-name parity claim is stronger than the implementation justifies.
- Silent ignored kwargs are worse than rejected kwargs.

Recommendation:
- Choose one:
  - implement a proper event-to-state conversion function with validated supported arguments, or
  - narrow the public contract and reject unsupported kwargs explicitly
- Do not advertise same-name parity for behavior that is still only a minimal pivot wrapper.

### Medium 7. `seqformat(long -> wide)` drops identifiers, making round-trips lossy

Affected file:
- `traminex/seqformat.py:49`

Problem:
- `seqformat(..., from_="long", to="wide")` performs a pivot and then `reset_index(drop=True)`.
- That discards the identifier column entirely.

Concrete repro run during audit:

```python
wide = pd.DataFrame({"pid": ["p1", "p2"], 1: ["A", "B"], 2: ["B", "C"]})
long = tx.seqformat(wide, from_="wide", to="long", id_col="pid")
back = tx.seqformat(long, from_="long", to="wide", id_col="id", time_col="time", state_col="state")
print(back.columns)
```

Observed output:
- only time columns remain; id is lost

Impact:
- The conversion helper is not a true invertible format transformation.
- The existing tests only check shape, so this data-loss bug is not detected.

Recommendation:
- Preserve the id as an actual column in wide output, or provide a `keep_id` option defaulting to `True`.

### Medium 8. `seqlogp(include_missing=False)` still includes missing positions in the summed log-probability

Affected file:
- `traminex/stats_complexity.py:224`

Problem:
- The state probabilities are computed from `seqistatd(..., include_missing=False)`, so missing states get zero probability.
- But the final sum still indexes `logp_states[x.data[i]]`, which includes missing-coded positions from the original sequence.
- Missing positions therefore contribute `log(eps)` instead of being excluded.

Concrete repro run during audit:

```python
z = tx.seqdef(np.array([["A", "*"], ["A", "A"]], dtype=object), nr="*")
print(seqlogp(z, include_missing=False))
print(seqlogp(z, include_missing=True))
```

Observed:
- `include_missing=False` produces a large negative penalty for the row containing `*`

Impact:
- Wrong semantics for the public `include_missing` flag.

Recommendation:
- Exclude missing-coded positions from the sequence-level sum when `include_missing=False`.

## 6. Architecture assessment

### What is working well

- Public API governance is centralized.
- Package layering is understandable.
- Optional-accelerator strategy is sensible.
- There is a real test suite, not just examples.
- The project includes parity/source tooling rather than relying on hand-maintained claims alone.

### Where architecture is weak

The dominant architectural issue is semantic duplication:

- Multiple constructors each implement their own encoding rules.
- Missing/void behavior is inferred differently in different subsystems.
- Event ordering assumptions are not modeled explicitly.
- Public option sets are duplicated across dispatcher, kernels, dataclasses, docs, and stubs.
- Generated parity artifacts are not automatically kept in sync with the manifest.

This creates "looks clean from the outside, diverges in edge cases" behavior. That is the main theme of the audit.

## 7. Recommended refactor direction

### Priority A. Unify sequence construction

Create one internal sequence-construction pipeline responsible for:
- alphabet policy
- metadata attachment
- missing / void code resolution
- labels / palette alignment

Then make:
- `seqdef`
- `seqdef_from_long`
- `TSE_to_STS`
- `HSPELL_to_STS`
- `events_to_state_sequences`

all terminate through that shared path.

### Priority B. Replace pseudo-supported options with real contracts

For `0.0.1`, remove misleading options now if they are not implemented:
- DHD `traminer`
- DHD `tmean`
- DUR `eps` if it will remain unused
- `dissdomassoc(weights=...)` if weighting will remain unsupported

Reject unsupported kwargs loudly instead of ignoring them.

### Priority C. Treat event ordering as first-class data

Store event input order in `EventSequence` and sort by:
- `id`
- `time`
- original row order

not by label.

### Priority D. Separate "parity naming" from "parity behavior"

Current docs sometimes drift toward "same function name exists, therefore parity".
That is too weak.

The project should distinguish:
- same-name exposure
- partial behavioral analog
- full behavioral parity

especially for `TSE_to_STS`, `HSPELL_to_STS`, and DHD-related claims.

### Priority E. Tighten release automation

Add CI checks for:
- manifest vs audit report counts
- generated report freshness
- all active docs, not just a subset
- semantic regression tests for the bugs above

1. Fix constructor metadata propagation first.
2. Fix event tie ordering second.
3. Fix cluster chronogram label handling third.
4. Remove or implement fake DHD variants and DUR `eps`.
5. Make `TSE_to_STS` reject unsupported kwargs or implement the missing behavior.

## 9. Release-readiness assessment

Current state:
- Good enough for exploratory use and internal iteration
- Not clean enough to present parity claims as fully reliable
- Still carrying a few public API contracts that are stronger than the runtime behavior

If this were my release gate for a first public version, I would not block release on every medium issue above. I would block on these before calling the release semantically trustworthy:

- constructor missing-metadata propagation
- event tie ordering
- cluster chronogram label crash
- fake DHD variants / ignored DUR `eps`
- stale parity report source-of-truth mismatch

## 10. Final assessment

This project has a strong base for a `0.0.1` sequence-analysis library. The best parts are the API manifest, the fallback distance architecture, the breadth of tests, and the existence of parity tooling. The biggest risk is semantic drift between adjacent subsystems that all appear to solve the same problem but do so with slightly different rules.

Because backward compatibility is not required, this is the right moment to remove misleading parameters, centralize encoding logic, and tighten the generated-document contract. Doing that now will prevent the current "mostly works, but edge semantics diverge" pattern from hardening into the public API.
